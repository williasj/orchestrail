Implement a thread-safe rate limiter that supports two interchangeable algorithms — token bucket and sliding window log — selectable at construction time via a strategy pattern (not if/else branching on a type flag). The limiter must expose allow(client_id: str) -> bool and be safe under concurrent calls from multiple threads against the same client_id. Token bucket should support configurable capacity and refill rate; sliding window should support a configurable window size and max requests per window. Include a simulation harness that fires at least 20 requests across at least 2 distinct client_ids, mixing both algorithms in the same demo run, and prints/returns an allow/deny decision log with timestamps for each call. State any concurrency assumptions explicitly.
